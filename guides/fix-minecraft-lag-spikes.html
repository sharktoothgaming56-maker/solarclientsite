How to Fix Minecraft Stutter and Lag Spikes

Stutter is a different problem from low frame rate, and it has a small number of distinct causes that each leave a recognisable signature. This guide is about identifying which one you have before you change anything.

Published September 20, 2026 · Applies to Minecraft: Java Edition 1.16–1.21 · ~11 min read

The short version

  • Regular, rhythmic spikes — every few seconds, evenly spaced — are garbage collection. Reduce heap size, fix GC flags.
  • Spikes only while moving into new terrain are chunk loading. Lower render distance, use Sodium.
  • Everything delayed, including block breaking is TPS, not FPS. Nothing graphical will help.
  • Random spikes while standing still are usually external: antivirus, overlays, or Windows itself.
  • Diagnose with the Alt+F3 frame time graph before changing a single setting.

Diagnose first

Stutter is frustrating enough that the instinct is to start changing things. That instinct is why people end up with twenty settings turned down and the stutter still there — they never established what was causing it.

The tool to use is the frame time graph. Press Alt+F3 (on some versions, hold F3 and press Alt). You get a live chart of how long each frame took. A smooth game is a flat line. Every spike is a frame that took too long, and the pattern of the spikes tells you what caused them.

Play for a minute or two in a spot where the stutter reliably occurs and watch the shape:

1. Garbage collection pauses

Signature: spikes at fairly regular intervals, roughly the same height each time, that continue even when you stand still in a fully loaded area.

Confirm it by watching the memory readout in the top-right of the F3 screen alongside the graph. Used memory climbs steadily, then drops sharply. If the drops line up with your spikes, that is the garbage collector, and you have your answer.

Three fixes, in order of impact:

Reduce your heap size

This is the one that surprises people. If you have allocated 12 or 16 GB, that is very likely the cause rather than the cure. A larger heap accumulates more garbage between collections, and collecting more takes longer.

Look at the low points of the memory sawtooth — that is what the game genuinely needs. Set your allocation to roughly two or three times that. For most setups it lands between 4 and 8 GB. The RAM allocation guide covers the reasoning properly.

Use proper collector flags

Default JVM settings optimise for throughput, which is the wrong goal for a game. Tuned G1GC flags — the widely used set is Aikar’s — lower the pause target and enlarge the young generation so short-lived objects are collected cheaply instead of being promoted. Java 21 and later also offer generational ZGC, which targets sub-millisecond pauses and suits large modded heaps.

SolarClient generates these automatically and scales the region and nursery sizing to your chosen allocation, because the correct values differ above and below roughly 12 GB.

Reduce allocation pressure

Less garbage created means less to collect. FerriteCore cuts the memory footprint of block states and models substantially. Lithium removes allocation in hot tick paths. MemoryLeakFix patches known retention bugs that otherwise force the collector to work against a heap that never properly empties.

2. Chunk loading and meshing

Signature: the graph is flat while you stand still and spikes as soon as you move, particularly when flying, using elytra, or travelling by boat or minecart. Worst in newly generated terrain.

Two separate pieces of work are involved. Generation creates terrain that has never existed before — expensive, but only once per chunk. Meshing converts block data into renderable geometry, and happens whenever a chunk enters view or its contents change.

In vanilla, a significant part of this lands on the main thread, so a frame that includes chunk work takes as long as that work takes.

What helps:

  • Sodium moves chunk meshing onto worker threads and rebuilds far less aggressively. This is the largest single improvement available.
  • Lower render distance. Loaded chunks scale with the square of the radius, so 16 is roughly four times the work of 8. Moving fast at high render distance is the single hardest thing you can ask the game to do.
  • C2ME parallelises chunk generation and I/O. It targets generation specifically, so it helps most when exploring new terrain rather than revisiting old.
  • Pre-generate your world if you run a server or a long-lived singleplayer world. Chunky generates terrain ahead of time so play never pays the generation cost.
  • Slow down. Not a fix so much as an acknowledgement — elytra flight at render distance 24 will hitch on any hardware, because the game cannot generate terrain faster than you cross it.

3. Disk activity

Signature: a cluster of spikes, then a long quiet stretch, repeating on a several-minute cycle. Often noticeably worse on a mechanical hard drive.

Minecraft autosaves periodically, writing modified chunks to disk. It also reads constantly while loading terrain. Anything that makes file access slow turns into stutter.

  • Antivirus real-time scanning is the most common cause. Every chunk file read and written gets scanned. Add exclusions for your launcher directory and your .minecraft or instance directories — specific folders, not the whole drive.
  • Cloud sync — OneDrive, Dropbox, Google Drive — will attempt to upload world files as they change. If your Minecraft directory sits inside a synced folder, move it out. OneDrive redirecting Documents by default catches a lot of people.
  • Mechanical drives. Minecraft’s access pattern is many small reads and writes, which is the worst case for a spinning disk. Moving the instance to an SSD is a large improvement if one is available.
  • A full drive. Below roughly 10% free space, both SSDs and Windows behave noticeably worse.

4. Background software

Signature: irregular spikes with no apparent relationship to what you are doing, including while completely idle.

Common culprits, roughly in order of how often they turn out to be responsible:

  • Discord’s in-game overlay. A long-standing source of hitching in Java applications specifically. Turn it off for Minecraft and test — this alone resolves a surprising share of reports.
  • Browser tabs. Modern browsers will happily consume several gigabytes and keep background tabs running timers. If you are short on RAM, this is also what pushes the system into paging.
  • Xbox Game Bar and background recording. Windows ships with background capture available, and it costs real performance when enabled.
  • RGB and peripheral software. iCUE, Synapse, Armoury Crate and similar poll hardware constantly and have a poor reputation for stability.
  • Windows Update. Downloads and installs in the background with no visible indication. If stutter appeared suddenly for no reason, check Update history.
  • Thermal throttling. Not software, but it presents identically. If stutter arrives only after twenty minutes of play, check temperatures — clean the fans before changing settings.

The reliable way to test this class of cause is to close everything, reboot, and launch only Minecraft. If the stutter disappears, add programs back one at a time.

5. When it is TPS, not FPS

Signature: the frame time graph is flat and the FPS counter is healthy, but the game still feels wrong. Blocks take a moment to break. Mobs stutter or teleport. Items you drop hang in the air. Doors open late.

That is the world simulation falling behind, not the renderer. Minecraft targets 20 ticks per second; below about 18 it becomes perceptible. No graphics setting affects it.

On a multiplayer server, this is the server’s problem. If everyone online is experiencing it, nothing you do locally will change anything — report it to the administrators.

In singleplayer, your machine is running the server too, so it is yours to fix:

  • Lower simulation distance. Separate from render distance since 1.18 and frequently left high by accident. It controls how far the world keeps ticking. Most players notice nothing at 8.
  • Look at your farms. Large mob farms, item elevators, and hopper chains are the usual cause. Hoppers in particular are expensive — a few hundred of them will measurably reduce TPS.
  • Check redstone. Clocks left running, observer loops, and update-suppression contraptions can consume the entire tick budget on their own.
  • Install Lithium. It optimises exactly this: pathfinding, block ticking, collision, entity management. It changes no behaviour.
  • Profile it. /spark profiler start, play a minute, /spark profiler stop. The report names the specific code eating your tick time, which beats guessing.

Stutter specific to modded setups

Large modpacks add failure modes of their own:

  • A single badly behaved mod. Some mods scan every player’s inventory every tick, or run world queries that should be cached. Spark identifies these by name. Binary search — disable half the pack, test, repeat — works when profiling is inconclusive.
  • Resource pack and model memory. Very large modpacks load enormous numbers of models and textures. ModernFix’s dynamic resource loading helps significantly here, as does FerriteCore.
  • Worldgen mods. Packs with heavy custom terrain generation shift the cost dramatically toward chunk generation. Pre-generating the world is the real fix.
  • Shader packs. The shadow pass renders the scene an additional time from the sun’s point of view, so scene complexity costs roughly twice. Lowering shadow distance and resolution is far more effective than lowering anything else in the pack.

A practical order of attack

  1. Open Alt+F3 and characterise the spike pattern. Do not skip this.
  2. If spikes are rhythmic: lower your RAM allocation to 4–6 GB and apply proper GC flags.
  3. If spikes track movement: install Sodium and drop render distance to 10–12.
  4. Turn off the Discord overlay and any recording software.
  5. Add antivirus exclusions for the launcher and instance directories.
  6. Confirm the game is running on your dedicated GPU, not integrated graphics.
  7. If the world feels delayed rather than choppy, lower simulation distance and profile with spark.
  8. Retest after each change, in the same spot, for at least a minute.

Most stutter resolves within the first three steps. The discipline that matters is changing one thing at a time and measuring — otherwise you end up unable to say which change helped, and carrying four unnecessary ones forever.
