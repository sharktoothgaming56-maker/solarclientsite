Reference

Every Minecraft Performance Mod, Explained

Performance mod lists are everywhere. What is usually missing is what each one actually does, so you can tell which ones address your problem and which are doing nothing for you. This is that reference.

Published September 20, 2026 · Applies to Minecraft: Java Edition 1.16–1.21 · ~13 min read

The short version

  • Start with four: Sodium, Lithium, FerriteCore, ImmediatelyFast. They cover rendering, ticks, memory, and GUI drawing.
  • Frame rate and tick rate are separate problems. Sodium does nothing for TPS; Lithium does nothing for FPS.
  • More mods is not better. Several popular ones overlap, and a few conflict.
  • Match the mod to the symptom — the categories below are organised for exactly that.

Four things a performance mod can fix

Almost every mod in this space targets one of four bottlenecks. Knowing which is yours narrows the list immediately.

  1. Rendering (FPS). How efficiently geometry reaches your GPU. Symptom: low frame rate, worse at high render distance.
  2. Game logic (TPS). How efficiently the world simulates. Symptom: delayed block breaking, rubber-banding mobs — while FPS stays fine.
  3. Memory. How much the game holds and how much garbage it makes. Symptom: rhythmic stutter, or out-of-memory crashes.
  4. Loading. Startup time, chunk generation, world load. Symptom: long waits, hitching while exploring.

Rendering mods

Sodium

Fixes: FPS. Priority: install this first.

Replaces the chunk rendering pipeline with one written against modern OpenGL. Vanilla issues a great many small draw calls; Sodium packs geometry into large shared vertex buffers and submits it in batches, culls more aggressively, and moves chunk meshing to worker threads. It adds no features and changes nothing visually.

This is the single largest improvement available to most players, and everything else on this page is a refinement by comparison. Fabric-native, with official NeoForge support in recent versions.

Iris

Fixes: adds shader support on top of Sodium.

Loads OptiFine-format shader packs. Not a performance mod in itself — shaders cost frames — but because it runs on Sodium’s faster base, shaders generally perform better under Iris than under OptiFine. Its Fabric installer bundles Sodium, so installing Iris usually installs both.

ImmediatelyFast

Fixes: FPS, particularly in GUI-heavy situations.

Minecraft still uses immediate-mode rendering for text, items, GUI elements, and particles — submitting geometry one piece at a time. ImmediatelyFast batches it. The effect is largest exactly where people notice drops: open inventories, full chests, busy HUDs, screens with many item icons. Complements Sodium rather than overlapping with it.

EntityCulling

Fixes: FPS in entity-dense areas.

Vanilla renders entities based on a coarse frustum check, so mobs behind walls are still drawn. EntityCulling runs asynchronous occlusion tests and skips entities and block entities that genuinely cannot be seen. Large gains in mob farms, villages, and busy servers; near zero in an empty field.

More Culling

Fixes: FPS, overlapping partly with EntityCulling.

Extends culling to block entities, item frames, armour stands, and leaf blocks. Useful, but check for overlap — running it alongside EntityCulling is usually fine, but running three culling mods is not three times better.

Nvidium

Fixes: FPS at very high render distance — on specific hardware only.

A Sodium extension using NVIDIA mesh shaders. Requires a Turing-generation card or newer (RTX 20-series and up). Where it applies, it allows dramatically higher render distances than otherwise practical. Not compatible with shaders, and useless on AMD, Intel, and older NVIDIA cards.

Distant Horizons

Fixes: view distance without the usual cost.

Renders far terrain as simplified level-of-detail geometry, so you can see for hundreds of blocks at a fraction of what an equivalent render distance would cost. Technically it spends performance to buy distance, but the exchange rate is far better than raising render distance. Shader compatibility has improved considerably but still needs matching versions.

Game logic mods

Lithium

Fixes: TPS. Priority: install alongside Sodium.

Optimises the tick loop — pathfinding, block ticking, collision detection, entity management, chunk handling. Makes no changes to game behaviour, which means it is safe on servers and will not break farms or redstone. If your world feels delayed rather than choppy, this is the mod for that.

Note the division of labour: Sodium addresses frames, Lithium addresses ticks. They solve different problems and most players want both.

Krypton

Fixes: network performance on multiplayer.

Optimises Minecraft’s networking stack. Modest but real on busy servers and on higher-latency connections. Irrelevant in singleplayer.

Starlight

Fixes: lighting engine performance.

A rewrite of the light engine, which in vanilla is a notable source of chunk loading cost. Historically this was one of the biggest wins available. On modern versions it has been folded into Moonrise, which combines it with chunk system improvements — check which is current for your version rather than assuming.

Moonrise

Fixes: chunk system and lighting, on modern versions.

The successor to Starlight, bringing chunk loading and light engine rewrites derived from server-side work. Noticeable during exploration and world loading.

Memory mods

FerriteCore

Fixes: memory usage. Priority: install it — it is essentially free.

Reduces the memory footprint of block states, models, and multipart predicates. The savings are large in modded setups, where thousands of block variants exist. Less memory in use means less garbage collection pressure, which means fewer stutter spikes. It has no downside worth mentioning.

ModernFix

Fixes: memory and startup time, especially in large modpacks.

A collection of patches rather than a single change: dynamic resource loading so not everything is held at once, faster startup, and assorted memory reductions. Its effect scales with pack size — substantial on a 300-mod pack, marginal on vanilla plus five mods.

MemoryLeakFix

Fixes: genuine memory leaks.

Patches known leaks in vanilla and in commonly used libraries. If your memory usage climbs steadily across a session and never returns to baseline after collection, this is the category of fix you need. It cannot fix leaks in arbitrary third-party mods.

Loading and generation mods

C2ME

Fixes: chunk generation and I/O speed.

Parallelises chunk generation and loading across cores. Large improvement when exploring new terrain; little effect when revisiting already-generated areas. Because it touches the chunk system deeply, check compatibility with other chunk-related mods before adding it to an established pack.

Noisium

Fixes: worldgen speed, more conservatively.

Optimises the noise generation stage of terrain generation. A lighter-touch alternative to C2ME with less risk of interaction problems.

Fastload / Dashloader

Fixes: startup and world load times.

Reduce the wait when launching the game or opening a world. They do nothing for in-game performance — worth it if you restart often, irrelevant if you play long sessions.

Exordium

Fixes: GUI rendering cost.

Renders HUD and GUI elements at a lower frequency than the game frame rate, on the reasoning that a hotbar does not need updating 200 times a second. Effective, but be aware it is a trade — some HUD elements will visibly update less smoothly.

What to actually install

For most people, in this order:

PriorityModsWhy
EssentialSodium, Lithium, FerriteCore, ImmediatelyFastCovers rendering, ticks, memory, and GUI. Little downside, broad benefit.
Strongly recommendedEntityCulling, ModernFix, MemoryLeakFixLarge gains in specific common situations.
SituationalC2ME, Krypton, Moonrise, ExordiumWorth adding when their specific symptom is yours.
Hardware-specificNvidiumOnly on NVIDIA Turing or newer, and not with shaders.
Add if you want the featureIris, Distant HorizonsThese spend performance to buy visual quality.

SolarClient ships the essential tier and most of the recommended tier pre-configured and version-matched. That is convenience, not exclusivity — every mod here is open source and freely available from Modrinth, and installing them by hand works exactly as well.

Common mistakes

  • Installing every mod on a list. Several overlap. Running three culling mods together adds conflict risk without adding much benefit.
  • Mixing Sodium and OptiFine. Both replace the rendering engine. This crashes immediately.
  • Mismatched versions. Performance mods touch internals and are strict about game version. A mod built for 1.20.1 will generally not load on 1.20.4.
  • Using deprecated mods. Phosphor was superseded by Starlight, which on current versions is superseded by Moonrise. Old guides still recommend Phosphor.
  • Expecting FPS mods to fix TPS problems. If blocks break late, Sodium will not help. That is Lithium’s department, or your simulation distance.
  • Forgetting Indium when a mod needs it. Some mods need the Fabric Rendering API, which Sodium historically did not implement. Recent Sodium versions cover much of it natively, so check before adding it reflexively.

Measuring the result

Install in stages and measure between them, in the same location, with the Alt+F3 frame time graph open. Installing eight mods at once and seeing an improvement tells you nothing about which of the eight you actually needed — and leaves you carrying seven you might not.

For diagnosis beyond the built-in graph, the spark profiler names the specific code consuming your frame or tick time, which is the difference between fixing a problem and guessing at it.
